# 인라인 마크업 감사·수선 설계 (스파이크 S2)

저장된 번역을 원문의 인라인 태그에 맞춰 느슨하게 다시 읽고, 태그 전송의 직렬화기로 다시 써서
깨진 마크업을 모델 호출 없이 고친다. `yeokja evaluate --audit`로 찾고 `--repair`로 고친다.
인라인 태그 전송 설계(`2026-09-22-inline-tag-transport-design.md`, 1b 문서)의 코덱을 그대로
쓴다.

## 1. 조사 (2026-09-22)

markdown 계열(`markdown`·`myst`·`mdx` 파서) 11개 프로젝트의 저장된 번역 41,483개를 각 방언의
렌더러(mdBook·GFM은 micromark gfm, MyST는 markdown-it-py와 nix-dev의 myst-parser 설정, MDX는
micromark mdx)로 읽어 원문과 구조를 비교했다.

| 결함 | 개수 | 프로젝트 |
|---|---|---|
| 단축·축약 참조의 글자를 번역해 링크가 끊김(`[team repo]` → `[팀 저장소]`) | 153 | rustc-dev-guide 116, rust-forge 27, webassembly-component-docs 8, zero-to-nix 2 |
| 기울임이 굵게로 바뀜(`*reviewing*` → `**리뷰**`) | 6 | rustc-dev-guide |
| MyST linkify 링크가 조사에 붙어 링크가 되지 않음(`cache.nixos.org를`) | 1 | nix-dev |
| 글자로 남은 강조 표시 | 1 | learn-fpga(원문도 짝 없는 `*`) |

그 밖에 코드 스팬 8건은 robustness 4절이 허용하는 덜어 내기(`Makefiles` → `Makefile`)라 결함이
아니다. 지난 세션의 수선으로 글자로 남은 강조는 거의 없어졌지만, 단축 참조 손실은 지금의 링크
평가기가 잡지 못해(1단계 A/B에서 확인) 그대로 남아 있다. 렌더링된 사이트에는 `[팀 저장소]`가
글자로 찍힌다.

## 2. 결정

### 2.1 결함 찾기와 다시 읽기

**결함 찾기.** 원문과 번역을 같은 방언·문맥으로 되읽어(직렬화기의 되읽기 확인과 같은 함수)
구문을 종류별로 센다: 기울임·굵게·취소선·링크(MyST 레이블 역할 포함)·인라인 HTML·각주·이미지·
자동 링크·표현식·줄바꿈. 번역이 원문보다 적게 가진 종류가 있거나 글자로 남은 강조 표시가
원문보다 많으면 결함이다. 코드는 세지 않는다(robustness 4절의 덜어 내기가 허용된다). 강조가
원문보다 많은 것(한국어 어순이 나눈 강조)은 결함이 아니다. **결함이 없으면 손대지 않는다** —
바이트가 달라도(이스케이프 표기 등) 바꾸지 않는다.

**다시 읽기.** 결함이 있는 번역만 원문의 `Tagged`를 기준으로 원문 번호의 태그 텍스트로 옮기고,
태그 전송과 같은 `read`(검증)와 `render`(직렬화)를 거친다.

1. 번역을 같은 방언·위치로 태그화하되 짝 없는 강조 표시가 있어도 거절하지 않는다.
2. 번역의 태그를 원문 태그에 맞춘다(원문 태그는 한 번씩).
   - 링크: 참조 레이블(`][label]`, 단축·축약 `[label]`)이 정규화해서 같거나, 인라인 링크는 꼬리
     (`](url)`)가 같은 것. MyST 레이블 역할은 (이름, 대상), 짝 맞는 인라인 HTML·JSX는 여는 태그,
     불투명 구문은 원문 바이트가 같은 것.
   - 강조: 종류별로 순서대로 먼저 맞춘다. 남은 번역 강조와 남은 원문 강조의 개수가 같고 **남은
     원문 강조가 한 종류일 때만** 종류를 넘어 맞춘다(`*reviewing*` → `**리뷰**`를 되돌림).
     한국어 어순이 굵게를 기울임 앞으로 옮긴 번역(`*only* … **nightly**` →
     `**나이틀리**에서 **오직**`)도 이렇게 해야 각 강조가 제 낱말에 남는다.
   - 코드와 글자 그대로 역할은 `read`의 코드 맞추기에 맡기고, 다시 쓸 때는 **번역이 쓴 스팬을
     그대로** 둔다(감사는 마크업만 고친다).
3. 맞추지 못한 번역 태그가 남으면(원문에 없는 강조·링크를 번역이 더함) 고치지 않는다.
4. 끊긴 참조 링크를 되살린다: 번역 글자 속의 대괄호 `[…]`·`[…][…]`(태그를 품어도 된다) 가운데
   원문에도 글자로 있는 것과 GFM 경고 표시 `[!…]`를 뺀 것을, 맞추지 못한 원문 참조 링크와
   개수가 같을 때 짝짓는다. 하나면 그대로, 여럿이면 번역 레이블에 남은 영어 낱말(두 글자 이상의
   ASCII 낱말)이 원문 레이블과 겹치는 쪽으로 짝지어 한 가지로만 정해질 때만 쓴다(한국어 어순이
   `[Rust signing key] … [available on keybase.io]`를 `[keybase.io에서 확인할 수 있는]
   [Rust 서명 키]`로 뒤집는다). 대괄호 바로 뒤의 `(레이블)`이 그 참조 레이블이면
   (`[beta로 백포트](backported to beta)`, 모델이 레이블을 목적지 자리에 쓴 것) 걷어 낸다.
5. 글자로 남은 강조 표시는 같은 글자·길이끼리 차례로 짝지어, 맞추지 못한 원문 강조와 개수가
   정확히 맞을 때만 되살린다. 맞추지 못한 강조가 없으면(번역이 강조를 둘로 나누고 한쪽을
   닫지 못함) 그 길이의 종류가 원문에 하나뿐일 때 그것으로 본다. 그 밖에는 고치지 않는다 —
   표시를 이스케이프해 글자로 굳히지 않는다.
6. 문자 참조(`&nbsp;`, `&#…;`)가 든 번역은 고치지 않는다. 다시 읽기가 이를 풀고 직렬화기는
   되돌리지 않으므로 보이지 않는 문자가 된다.
7. `read`가 문제를 내거나 `render`가 되읽기 확인에 실패하거나, 다시 쓴 결과에 결함이 남으면
   고치지 않는다.

결과는 **Sound**, **Repaired**(다시 쓴 Markdown), **Unrepairable**(결함과 사유) 가운데 하나다.
Repaired는 세그먼트 전체를 다시 직렬화하므로 결함과 무관한 곳의 이스케이프 표기(`2 * 3` →
`2 \* 3`, MDX의 `{`·`<`)도 직렬화기의 규칙으로 바뀐다. 렌더링은 같다.

### 2.2 명령

- `yeokja evaluate <path> --audit`: `markdown`·`myst`·`mdx` 파서 소스의 번역된 세그먼트를
  감사해 Repaired(고친 결과와 함께)와 Unrepairable을 보고한다. `inline_tags` 설정과 무관하다.
  모델을 부르지 않는다(평가기도 돌리지 않는다).
- `--repair`: Repaired를 state의 `translation`에 쓴다. `translated_at`은 바꾸지 않는다(기계적
  수선이며, README 출처 표기가 이 시각으로 번역 모델을 가늠한다). `source_hash`·`context_hash`도
  그대로라 `status --check`는 번역됨으로 본다. `issues`(번역 때의 평가 메시지)는 건드리지 않는다.
  출력(`ko/`)은 다음 `translate`가 재구성한다.
- 수선 목록(전·후)을 모두 출력한다. 건수가 많지 않아 사람이 훑어보는 것이 가장 싼 안전장치다.
- 태그화할 수 없는 원문(1단계 3.1)과 `Position::Plain` 세그먼트는 건너뛴다.

### 2.3 범위 밖

- Unrepairable의 재번역. 목록을 인계한다(태그 모드 소스라면 재번역이 태그 전송으로 간다).
- RST·AsciiDoc 등 다른 마크업(코덱이 없다).
- linkify 링크(1건): 모델이 URL 뒤에 조사를 붙인 것으로, 태그로 표현되지 않는 구문이다.

## 3. 검증

- 단위 테스트: 온전한 번역·나뉜 강조·덜어 낸 복수형은 Sound, 끊긴 단축 참조, 여러 참조의
  어순이 뒤집힌 것, 원문의 글자 대괄호, 레이블을 목적지 자리에 쓴 것, 강조 종류 바뀜(어순이
  바뀐 것 포함), 괄호 풀이 뒤에서 닫히지 않은 굵게, 나뉜 강조의 한쪽이 닫히지 않은 것, 태그를
  품은 대괄호, 문자 참조, 덧붙이거나 빠진 마크업은 Unrepairable.
- 말뭉치: 모든 markdown 계열 프로젝트에 `--audit`을 돌려 1절의 결함이 Repaired로 잡히는지,
  Sound인 세그먼트를 바꾸지 않는지(저장된 번역을 그대로 태그화한 왕복과 같은 성질) 본다.
- 수선 뒤: 같은 방언 렌더러 채점에서 결함 감소, 21개 Pages 프로젝트 `rebuild-translations.sh`
  통과, 수선한 프로젝트 빌드.
