# 인라인 태그의 이미지 대체 텍스트 설계

`inline_tags = true`인 Markdown 계열 파서(`markdown`, `myst`, `mdx`, `rmarkdown`,
`mkdocs`, `bikeshed`)에서 이미지의 대체 텍스트(alt)를 번역 대상으로 만든다.

## 원인

`translate::inline::markdown::tagify`는 `![alt](src)`를 통째로 빈 태그 `<xN/>`로
바꾼다(원문 그대로 복사하는 구성). 모델은 번역할 글자를 받지 못하고, 이미지 하나뿐인
문단은 원문 그대로 돌아온다. 저장된 state에 그 흔적이 있다: chip8-book 6, furiosa-opt
12, learninpublic 42, rustc-dev-guide 11, rust-forge 5, perf-ninja 2개의 이미지 단독
세그먼트가 영어 alt 그대로다. Hugo 블로그처럼 alt에 여러 문장의 설명을 쓰는 원문
(`![Diagram: one column of memory. … still registered.](stack-overflow.svg)`)에서는
본문 상당량이 번역되지 않는다.

## 결정

### 1. 이미지는 alt를 감싸는 짝 태그 `<gN>…</gN>`다

- 새 태그 종류 `TagKind::Image`, 글자 `g`. 링크(`<aN>…</aN>`)와 같은 방식이다.
  `open`은 `![`, `close`는 alt 뒤의 꼬리를 원문 바이트 그대로 담는다:
  `](src "title")`, `][ref]`, `][]`, `]`. 목적지와 제목은 모델에게 보이지 않고 그대로
  돌아온다.
- alt 안의 인라인 마크업(`![**x** y](i.png)`)은 링크 글자처럼 안쪽 태그가 된다:
  `<g1><b2>x</b2> y</g1>`. 링크 안의 이미지(`[![alt](i.png)](u)`)는
  `<a1><g2>alt</g2></a1>`로 중첩된다.
- 링크와 다른 글자를 쓰는 이유: 프롬프트가 `<aN>`을 "링크의 보이는 글자"로 설명한다.
  alt는 그림의 설명이라 번역 방식(문장으로 옮김, 고유명사 처리)이 다르고, 모델이
  둘을 구분해야 한다. 그래서 `INLINE_TAG_RULES`(`crates/translate/src/prompt.rs`)에
  `<gN>…</gN> the description (alt text) of an image`를 더한다. 커스텀
  `prompt_template`도 `{inline_tags}` 자리로 같은 규칙을 받는다.

### 2. alt가 비어 있으면 지금처럼 빈 태그다

`![](src)`에는 번역할 것이 없으므로 `<xN/>`(원문 그대로)로 둔다. 빈 짝 태그를 보내면
모델이 그 안에 말을 지어 넣을 여지만 생긴다.

### 3. 참조식 이미지는 링크와 같은 규칙을 따른다

`![alt][ref]`는 꼬리 `][ref]`가 그대로 돌아오므로 alt만 바뀐다. 레이블이 곧 alt인
단축·축약형(`![logo]`, `![logo][]`)은 링크의 단축 참조와 같이 alt가 원래 레이블과
같으면 원문 꼴로, 달라졌으면 `![번역][logo]`로 쓴다. 참조는 끊기지 않는다. 축약형
`![logo][]`는 alt가 그대로면 링크의 축약형과 똑같이 단축형 `![logo]`로 돌아온다(같은
HTML).

### 4. 제목(title)은 번역하지 않는다

`![alt](src "title")`의 제목은 꼬리에 묶여 그대로 돌아온다. 제목은 드물고, 번역하려면
태그 하나에 두 개의 글자 자리가 필요하다. 이번 범위 밖이다.

### 5. 읽기·직렬화·검증

- `read`: 이미지 태그는 링크처럼 정확히 한 번 열리고 닫혀야 한다. 원문 alt가 있는데
  응답의 짝 태그가 비어 있으면 문제("is empty — write its translated description
  inside it")로 돌려보낸다. 빈 alt를 저장하면 접근성이 원문보다 나빠진다.
- 직렬화: 여는 자리는 `![`, 닫는 자리는 꼬리. alt 글자 안의 `[`와 `]`는 링크 글자처럼
  이스케이프한다(`in_link`). 이미지 바로 앞 글자 판단에 쓰는 첫 글자는 `!`다.
- 다시 읽기(`Renderer::read_back`)와 의도(`intended`)는 이미지를 `(g…)`로 적고 alt를
  글자에 넣는다. 빈 alt의 빈 태그는 모양 `(g)`로 같은 키를 쓴다. 구성 키 `(g`의 이름은
  "image"다.
- 감사(`inline::audit`): `NOT_TO_GAIN`의 이미지 키를 `(g`로 바꾸고, 다시 읽기에서
  번역의 이미지를 원문 이미지와 꼬리(참조식은 레이블)로 짝짓는다.

### 6. "번역할 글자 없음" 경로

이미지 단독 세그먼트가 provider를 거치지 않는 경로가 있는지 확인했다.

- `untranslatable::nothing_to_translate`는 `](…)` 목적지만 빼고 글자를 센다. alt의
  글자가 남으므로 이미지 단독 세그먼트는 모델로 간다. `![](x.png)`처럼 alt가 비면
  지금처럼 요청 없이 원문을 번역으로 기록한다. 변경 없음(테스트로 고정).
- 미번역의 원인은 태그화뿐이었다. 다른 단락 경로는 없다.
- `evaluator_glossary::glossary_source`는 이미지 단독 세그먼트의 용어 검사를 끈다.
  이는 요청을 막지 않는 검사 범위의 문제이고, alt의 긴 설명에서 용어 형태를 강제하면
  재시도만 늘 수 있어 이번에는 그대로 둔다. alt에도 용어집을 강제하려면 그 함수에서
  `is_image_only` 조건을 빼면 된다(별도 변경).

## 기존 프로젝트에 미치는 영향

- 세그먼트 원문, `source_hash`, 블록 문맥 해시는 태그화와 무관하므로 바뀌지 않는다.
  `status --check`는 그대로 깨끗하다.
- 이미 저장된 번역은 건드리지 않는다. 영어 alt를 그대로 둔 번역도, 레거시 방식에서
  alt까지 옮긴 번역도 원문과 같은 구성(`(g…)`)으로 읽히므로 감사는 Sound, `gained`는
  비어 있다.
- 따라서 기존의 미번역 alt는 그대로 남고, 원문이 바뀌어 다시 번역되는 세그먼트부터
  alt가 번역된다. 한 페이지에 번역된 alt와 아닌 alt가 섞일 수 있으나 렌더링이 깨지지
  않고 지금보다 나빠지는 곳이 없으므로 받아들인다.
- 프로젝트가 기존 alt를 새로 번역하려면 해당 세그먼트의 state에서 `translation`을
  `null`로 바꿔(Pending이 된다) `yeokja translate`를 다시 돌린다. 대상은 원문이 `![`로
  시작하고 번역이 원문과 같은 세그먼트로 고를 수 있다.

## 범위 밖

- XHTML 계열(`<img alt>`)과 레거시(태그 없는) 경로.
- 이미지 제목의 번역.
